Встроенная копия: `src/shared/server-catalog.json`. Последний успешный каталог сохраняется в кэше лаунчера.

Параметры: `createsky.tralala.club:25565`, Minecraft 1.21.1, NeoForge **21.1.266**, Java 21. Адрес `188.127.241.249:25922` также отвечал на SLP при проверке. Порт 25922 к домену добавлять не требуется. Иконка и онлайн берутся через Minecraft Server List Ping с таймаутом 4 секунды и кэшем 20 секунд. Ошибка запроса означает неизвестный статус, а не ноль игроков.

Клиентские файлы загружаются из выбранного репозитория Create-Aeronautics-Skybound, из папки `pack/`, по зафиксированному commit. SHA-256 опубликованного `pack-index.json` и каждого файла проверяются. Требуемый NeoForge задаётся каталогом сервера: старые сведения 21.1.259 в исходном индексе не используются для выбора загрузчика.

В исходном наборе 395 JAR-файлов. Для серверного профиля каталог исключает два старых дубликата: Balm 21.0.63 и Moonlight 3.1.2. Остаются Balm 21.0.66, Moonlight 3.7.2 и всего **393 JAR-файла**. Исключения закреплены по имени и SHA-256. Исходные файлы GitHub не удалены.

## Использование

Выберите аккаунт, откройте «Серверы» и нажмите «Играть». Лаунчер проверит Java, установит точную версию игры и NeoForge, подготовит файлы, затем передаст Minecraft аргумент `--quickPlayMultiplayer createsky.tralala.club`. Полноценный вход зависит также от авторизации, whitelist и совместимости набора с сервером.

«Моды» показывает фактически установленные JAR-файлы с поиском. «Папка» открывает игровую папку сервера. «Логи» показывает вывод клиента. Во время подготовки доступна отмена; установщик Minecraft/Java заканчивает текущий этап, после чего запуск отменяется. Загружаемые файлы сборки отменяются сразу. Повторный клик не создаёт вторую задачу.

## Файлы пользователя

Для каждого ID создаются `<папка игры>/servers/<id>/game` и `runtime`. Обычные профили версий и сборок не мигрируют. Миры, options.txt и посторонние файлы не удаляются. Настройки config/defaultconfigs сохраняются, если соответствующий файл не менялся в опубликованной сборке. Изменение такого файла автором сборки применяется с резервной копией.

Сначала скачиваются и проверяются все изменённые файлы. Затем применяется обновление с журналом восстановления. При ошибке восстанавливается предыдущая ревизия. Резервные копии заменённых файлов находятся в `servers/<id>/backups`. Старые управляемые файлы удаляются только после успешной загрузки нового набора. Незавершённые временные загрузки при повторе скачиваются заново.

## Обновление владельцем

### Автоматическая публикация (лаунчер 1.0.11 и новее)

Загрузите нужные клиенту JAR-файлы и зависимости в `pack/mods/` ветки `main` репозитория `Ujif416/Create-Aeronautics-Skybound`. При замене удалите прежнюю версию JAR. Аналогично можно обновлять конфиги и другие разрешённые папки внутри `pack/`. На игровой сервер моды загружаются отдельно; серверные моды, не предназначенные для клиента, в GitHub-набор не добавляйте.

Дождитесь зелёного результата **Actions → Publish client pack**. Workflow автоматически пересчитывает размеры и SHA-256, фиксирует индекс отдельным коммитом и публикует ссылку на этот неизменяемый снимок в каталоге сервера. Все коммиты отправляются одним push; принудительной перезаписи истории нет. При ошибке публикации предыдущая опубликованная версия остаётся доступна. Новые изменения в main запускают следующую проверку; также доступна кнопка Run workflow.

Игрокам нужно один раз установить MossLauncher 1.0.11. При каждом нажатии «Играть» в разделе «Серверы» запрашивается свежий каталог. Если проверить обновления не удалось, запуск блокируется с предложением повторить. Затем проверяются файлы, скачиваются изменения, и только после успешной синхронизации запускается Minecraft. Уже запущенная игра обновляется при следующем запуске. Автоматизация проверяет целостность файлов, но не устанавливает совместимость произвольных модов и не подбирает зависимости.

Ниже — устройство публикации для ручного обслуживания; при обычной загрузке модов эти действия выполняет workflow.

1. Подготовьте совместимый **клиентский** набор в `pack/`, обновите размеры и SHA-256 в `pack-index.json`, опубликуйте commit.
2. В `launcher/servers.json` измените `pack.commit`, `pack.indexSha256`, `packRevision` и при необходимости точную версию NeoForge. Хеш индекса вычисляйте по байтам, опубликованным GitHub: преобразование CRLF/LF меняет его.
3. Пересмотрите исключения: их имена и хеши должны присутствовать в новом исходном индексе. Удалите исключения, если дубликатов больше нет.
4. Проверьте чистую установку и подключение до распространения обновления.

В этой версии поддержан указанный Minecraft 1.21.1 / NeoForge / Java 21. Каталог не является универсальным импортом произвольных серверов, SRV и IPv6. Файлы игрового сервера и панель хостинга не используются как источник клиентских модов. Каталог принадлежит владельцу GitHub; доступа к токенам хостинга лаунчеру не требуется.
